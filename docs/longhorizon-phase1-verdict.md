## 2.6 拆分为什么不划算:是实现的缺陷,不(只)是思路的问题

补跑全量思考记录后,在 trace 里指到了具体机制。三个上限互相打架:

| 上限 | 值 | 作用域 |
|---|---|---|
| `MAX_LOOP_STEPS` | 16 | 主脑自己的步数 |
| `SUBAGENT_MAX_STEPS` | **4** | 每个子 agent 自己的步数 |
| `MAX_VIDEOS_PER_REQUEST` | 12 | **整棵树共享**的视频分析配额 |

`pipeline/subagents.py:12` 让子 agent 复用父请求的 execute 闭包 —— 这是对的(防止拆分
绕过成本闸)。问题在 `pipeline/subagents.py:184`:未收敛时只返回一句
`"(子 agent 未收敛:max_steps)"`。

**账是不对称的**:子 agent 每看一个视频就从全树 12 个配额里扣一个、钱真花了(不可逆),
失败时却返回零信息。主脑接手时**既没有结论,也没有配额自己补看**。

`t1-cheering` C 臂那次把话说全了 —— step 7:"my sub-agent didn't converge as expected
(max_steps)... I can proceed by directly invoking analyze_video myself";step 8:看到
「已达本请求视频分析上限(12 个)」,"It dawned on me that my prior spawn_agents calls
likely involved multiple internal analyze_video invocations, accumulating to hit the
ceiling."最后它只能靠 `semantic_search` 的**文字片段**收口,而不是看画面。

留痕可见的发生率:**子 agent 未收敛 5/19 次拆分**(这是下界 —— main-v3 那批只存前 6 轮
思考,子 agent 通常第 6 步后才回来)。

**修法(已实施,commit `952f2dc`;都不需要深度 2,是把已有的一层拆分修到及格)**:

1. ~~**失败退配额**~~ —— **这条是错的,已撤回**。钱已经花出去了,把 quota 计数减回去只会让
   整棵树实际花掉两倍于 `MAX_VIDEOS_PER_REQUEST` 的预算,直接废掉成本闸的语义。
   配额管的是"最多调几次 Gemini",不是"最多拿到几个有用结论"。
   **正确的方向是把已经买到的东西交回来,不是再给一次预算。**
2. ✅ **失败也交回已买到的结果**(`subagents._salvage_analyses`)—— 撞 max_steps / repeat /
   熔断时,按 cid 关联 `r.trace` 与 `r.ledger`,把**已成功执行的 analyze_video 结论**
   带回主脑,诚实标注"未经子 agent 综合"。闸门信封(`gate=="blocked"`)排除 ——
   把一句"已达上限"当证据回流是灾难。捞不到时逐字节退回原行为;
3. ✅ **步数按活配**(`subagents._steps_for`)—— `min(CAP, max(SUBAGENT_MAX_STEPS,
   len(video_ids)+2))`,per-task 不是全局;新增 `SUBAGENT_MAX_STEPS_CAP`(默认 8)封顶。
   **没点名 video_ids 时恒等于基线,与动态化之前逐字节一致。**
4. ✅ **基线 4→6**(`2a75da9`,补跑实测定的)—— 14 个真机子 agent:给 4~5 步的 10 个
   **无一收敛**,给 6 步的 4 个**全部收敛**。且与"派了几个视频"无关:同一步内 analyze 是
   并行的,N 个视频本来一步能看完;卡死的是**固定开销**(定位 1~2 步 + 看 1 步 + 汇总 1 步
   ≈ 4,4 步等于零余量)。实测有子 agent 拿 2 视频/4 步,**一个视频都没看成**就撞墙。
   所以 §2.6 原本给的 `N+2` 斜率方向对、**基线定错了**。

**同一批补跑也是残值回收的真机验证**:10 个撞墙的子 agent 共捞回 **16 条**视频分析,
按修复前的代码这 16 条全部丢弃。**子 agent 撞墙率实测 10/14 = 71%**,远高于上面从
留痕估的下界 5/19 —— 因为老跑机只存前 6 轮思考,大部分根本看不见。

**还没修的第三条:配额是暗的。** 主脑决定拆不拆时看不见配额余额 —— 全代码库里
`quota["analyzed"]` 只在**拦截那一刻**被读,没有任何地方把余额告诉大脑。它只有撞墙才知道
(实测 trace 的 step 8 就是那一刻)。看不见余额做不好资源决策,但这是独立的一件。

**这改变了"不建"的性质**:成本 2.4 倍是实测的,但其中一部分是**失败模式的浪费**,
不是拆分的固有代价。修完这三条再测,成本差会变小。**"不建深度 2"仍然成立**
(深度 2 只会让这个账更糟),但**"一层拆分不划算"应降级为"当前实现下不划算"**。

## 2.7 【第 9 个缺陷】深度 2 从未触发 —— C 臂和 B 臂是同一个东西

带参数录制的补跑(2026-08-02,`evals/runs/gate-spawnshow.jsonl`)第一次看见了主脑
**实际写给子 agent 的分活内容**。查到的第一件事就推翻了 §1。

子 agent 要能再拆,得同时过六道闸:`USE_DEPTH2=1` → 发起者 `depth==0` →
**它手里得有 `spawn_agents` 这个工具** → "先自己试"闸(本枝代码计数成功 ≥2 次工具)→
L2 扇出 ≤3 → 全树节点 ≤13。

**卡死在第三道**(`subagents.py:84`):

```python
allow = [x for x in req if x in allowed] or list(_SUBAGENT_DEFAULT)
```

主脑不写 `tools` 就落到默认集,而默认集**不含** `spawn_agents`:

```
_SUBAGENT_DEFAULT = ('analyze_video', 'semantic_search', 'sql_query')
_allowed(0)       = (..., 'web_search', 'spawn_agents')      ← 白名单里有
tools=None → 子实得 ['analyze_video','semantic_search','sql_query']  ← 默认集里没有
```

**真机 14 段子任务,`tools` 全部是 `None`,一次都没指定过。** 每个子 agent 拿到的都是
没有 `spawn_agents` 的三件套 —— 手里没这个工具,想拆也拆不了。`_run_one` 里那段
"你握有 spawn_agents…"的系统 prompt(`subagents.py:121-124`)一次都没触发过。

主脑也**没有理由**去指定:工具描述里 `tools` 那栏写的是"**限**它只能用的工具子集
(默认 analyze_video/semantic_search/sql_query)"—— 一句限权说明,列出的默认不含
spawn_agents,全文没有任何一句告诉主脑"你可以把再拆的权力授下去"。

### 后果

C 与 B 的**唯一差异**就是那条白名单,而它从没被用到 → **v3 的 78 次跑里 C ≡ B**。

| 受影响的结论 | 状态 |
|---|---|
| §1"这是**测过之后**的不建" | **错**,深度 2 没跑过 |
| R2 判据 `T2 上 C−B = +0.043` | **测的是两个相同臂之间的噪声**(噪声地板 0.112,完全吻合) |
| R4 阴性对照 `T1 上 C−B = +0.034` | 同上 |
| "一层拆分不划算" | **不受影响**(那是"拆了 vs 没拆"的对照,与深度无关) |

**"不建深度 2"作为决策仍然成立**(一个从没跑起来的功能没有已证实的价值),但它是
**"没测过所以不建"**,不是**"测了发现不行"**。这是同一个实验第三次栽在假前提上:
v1 是拆分率恒 0;v2/v3 是 gold 缺陷;现在是深度 2 压根没触发。

### 要真测深度 2,先修这个

至少三选一:① `_SUBAGENT_DEFAULT` 在 `USE_DEPTH2=1` 且 depth=0 时带上 `spawn_agents`;
② 工具描述里明说"可以把再拆权授给子 agent,写法是 tools 里带上 spawn_agents";
③ 实验专用开关强制给。**在此之前不要再跑 C 臂 —— 那是在花钱复制 B 臂。**

## 3. 功效诚实声明:本实验测不出 +0.10 的效应

A 臂(**没有** spawn 工具,两次完整跑之间配置**逐字节相同**)的漂移:

| 档 | v2 | v3 | 差 |
|---|---|---|---|
| T1 A | 0.198 | 0.310 | **+0.112** |
| T2 A | 0.358 | 0.382 | +0.024 |

**同一个配置,跨轮次漂移 0.112 —— 超过判定门槛 0.10。**
(另:v2 里 B≡C 的分差平均 0.093,同题同臂两跑差平均 0.057、最大 0.411。)

所以"不建"是一个**决策**(没看到收益 + 确实更贵),**不是**"已证明无用"这种科学结论。
要真正判定 ±0.10 量级的效应,题量或 rep 数至少要翻倍。

## 4. 红线回归:诚实探针从 6/6 掉到 4/6

空集题("找出库里所有打高尔夫的视频",库里没有):

- v2(prompt 修复前):**6/6 全对**
- v3(修复后):**4/6**,A 与 C 各有一个 rep 报了假阳性

两次失败锁定同一条视频 `v_08wKlw4a_so`,标题 **"Raking Leaves: A Friendly Wave from
the Yard"(在院子里耙树叶)**。agent **看了这个视频**,视觉模型把耙树叶的挥动读成高尔夫
挥杆,然后毫不含糊地报"库中共有 1 个打高尔夫的视频",还给了时间段和"画面证据"。

**不是凭空编造,是感知错误被自信转述。** 但对空集探针而言后果一样:红线破了。

**可立即行动的修法**:agent 手上有标题("耙树叶")却没和视觉结论("高尔夫")交叉核对。
加一条廉价的自检 —— 视觉结论与标题/库内谓词明显冲突时降置信或弃权 —— 就能拦住。
**这条比深度 2 值钱得多。**

(是否由本轮 prompt 改动诱发,证据不足:B 臂同 prompt 同 rep 答对了。更可能是
"去看视频核实"这个正确行为撞上了视觉模型的误读。)

## 5. 净收获清单

**已确立的事实**

1. **深度 2 不建**(有拆分发生的前提下测得),代码保留、开关默认关;
2. **拆分本身在当前任务分布下不划算**:更差、2.4 倍成本、1.6 倍耗时;
3. **本实验规模测不出 ±0.10** —— 任何后续 gate 都要先补功效;
4. **历史成本数字系统性低报 2.6 倍**(旧账本不计思考 token);
5. **零交付率**:A 臂 v2 5/26 → v3 2/26(跑道提醒 + 交付契约的效果),B/C 各 ≤1/26 ——
   **拆分的第一收益是"至少交得出货",不是"答得更好"**。

**九个会让实验"看起来有结果、其实全假"的缺陷(1-6+8 已修;7 gold 待修;9 待修)**

| # | 缺陷 | 后果 |
|---|---|---|
| 1 | spawn 描述只有刹车、两条判据结构性排除本场景 | **拆分率恒 0,裁决建立在假象上** |
| 2 | 判分口径与产品规则冲突(要 id,而 VS 按规则洗成"第 N 个") | 每一臂恒 0 分 |
| 3 | T2 防 SQL 捷径从没实现 | 查库抄时间戳,一个视频不看也能答 |
| 4 | analyze 缓存键不含命名空间 | 三臂共享暖缓存,"全口径成本"是假的 |
| 5 | 熔断预留按 pro 一刀切估价 | 实花 $0.13 顶掉 $0.80 的闸,**专罚看视频多的臂** |
| 6 | 跑机 surfaced 取"碰过的一切" | gold=3 的题抓到 37 条 |
| 7 | gold 用精确谓词匹配,漏词序变体与更具体谓词 | 71% 的"超发"是误判,**质量结论全部作废**(§2.5) |
| 8 | 跑机只存工具【名字】,不存 spawn 的分活内容 | 拆分质量的全部内容都在 instruction 里,等于没记 |

**下一步建议(按价值排序)**

   在此之前**任何质量结论都不可信**,包括本文的;
